## Decisions made by the user (keep these)
- Renderer default stays `"auto"` (hardware D3D11, WARP fallback). `"software"` is available in config.json for ~8 MB private bytes instead of ~65 MB; the difference is the NVIDIA user-mode driver.
- No working-set trimming hacks (no `SetProcessWorkingSetSize`). Report real numbers.
- Taskbar fully hidden while running; dock floats and auto-hides (macOS behaviour, Phase 5).
- Efficiency over features; no large dependencies.

## If the taskbar is missing
The dock hides it. Run `WinDock.exe --restore-taskbar`, or simply launch and quit the dock. If that fails, restart Explorer: `taskkill /f /im explorer.exe && start explorer`.

## Testing cautions learned
- Do not use Notepad as a test app on this machine; it restores unsaved tabs and pops a save dialog.
- `explorer.exe C:\` opens tabs in the existing window on this build, so it cannot be used for a two-window test. Use two `mspaint.exe` windows.
- Listary's `SearchBarWindow` appears next to file dialogs; the tracker ignores `WS_EX_NOACTIVATE` windows without `WS_EX_APPWINDOW` for this reason.
- Always finish a test run with `--quit` and confirm `Shell_TrayWnd` is visible and no `WinDock` process remains.
- Hidden test messages (registered window messages, all documented in README.md): `WinDock.QueryItemPoint`, `WinDock.ItemCommand` (800 pin toggle, 801 new window / bin Open, 802 file location, 803 folder in Explorer, 804 Choose icon dialog, 805 reset icon, 806 folder popup toggle, 807 empty bin, 808 Choose image dialog, 900 close all), `WinDock.DockCommand` (100 auto-hide toggle, 101 hide taskbar, 102 autostart, 103 open config, 104 show taskbar until re-enabled, 105 quit, 106 reload config, 107 settings window, 108/109/110 auto-hide off/always/intelligent, 111 refresh weather, 112 add separator, 113 weather settings, 114 calendar popup toggle, 115 weather popup toggle), `WinDock.QueryState` (0 auto-hide state, 1 notification state, 2 hovered item, 3 label visible, 4 magnifying, 5 pending timers, 7 drag state, 9 insertion index, 11/12/13 preview popup visible / cards / card window, 14 auto-hide mode, 15 overlapped, 17 reduce motion, 19/21 foreground-watch counters, 20 theme resolve failed, 22/23 folder popup visible / entries, 24 item kind, 25 item custom icon, 26 drop mode, 27 weather state (0 none, 1 stale, 2 fresh, 3 error), 28 temperature x 10 (`INT_MIN` none), 29 weather popup visible, 30 seconds since the weather fetch (-1 none), 31 calendar popup visible, 32 icon effects applied (bit 0 glow, 1 reflection, 2 perspective), 33 glow opacity target x 100, 34 reflection surface height px, 35 item dominant colour; 24/25/33/34/35 take the item index in `lParam`).
- QueryState 5 does not count launch bounces. To check that a click did not bounce, watch the dock HWND's height: a bounce keeps it at stage size (128 px at 100 %) for up to 5 s, otherwise it compacts to the bar (64 px) about 200 ms after the mouse leaves.
- Test configs must keep `"startWithWindows": true` (the user's setting): Reload config (DockCommand 106) applies it to the Run key.
- With `autoHide` `"off"`, a window that is maximized and activated (two `mspaint.exe` windows open maximized here) can end up above the topmost dock, so hover tests miss the dock. Restore and shrink the test windows first (`ShowWindow(SW_RESTORE)` + `MoveWindow`). Seen while testing 8.0; z-order code was not changed, so this is most likely an existing gap of the "off" mode (only hide transitions re-assert topmost).
- The machine may be in use during a test run (during the 8.0 run the pins were reordered and the cursor moved without the test script doing it); re-read the item list before asserting on positions or order.
- Folder / Recycle Bin click tests open Explorer views in the user's Explorer window (tabs); leave them, closing a tab window via `Shell.Application` can close the user's other tabs.
- PowerShell P/Invoke: pass `[NullString]::Value` (not `$null`) as the title to `FindWindowW`; `$null` binds as "" and matches only untitled windows. Build from PowerShell: in Git Bash `cmd /c` gets its `/c` path-mangled.
- Click popups (the folder popup; later weather / calendar) are activatable: opened by a real click on the dock they take the foreground, so Escape and clicking another window close them. Opened by `WinDock.ItemCommand` 806 they usually cannot take the foreground (the dock did not receive the input): Escape does not reach them, but another window coming to the foreground, a dock click or 806 again closes them. Before clicking "into" a popup in a script, check `QueryState` 22 is 1: a dock click on an open folder's icon toggles it closed, and the click then lands in whatever window is behind (twice during 8.1 testing it landed in the user's Chrome window).
- Recycle Bin tests: recycle only a temp file of your own (`Microsoft.VisualBasic.FileIO.FileSystem::DeleteFile(..., SendToRecycleBin)` or a scripted drop), then take it back out with `Shell.Application` (`Namespace(10)`, find the item by name, `MoveHere` it to a temp folder, delete it). Never run Empty Recycle Bin (`ItemCommand` 807) unless the bin holds only your own files; during 8.1 it held ~200 of the user's items, so Empty and the full -> empty icon switch were not run.
- Scripted OLE drags work from PowerShell: a small topmost WinForms form as the source, `mouse_event` left-down, then `Application.DoEvents()` a few times BEFORE `DoDragDrop` (the drag loop reads the thread's synchronous key state; without that the drag ends at once), and a second process moving the cursor (`SetCursorPos` + small real moves) and releasing. The source form is itself a new window on the dock (an extra running item re-centres the dock by half a slot), so locate items after it appears. Scripts: session scratchpad `p1\drag.ps1`, `p1\mover.ps1`.
- Do not use `IApplicationActivationManager::ActivateForFile` on packaged desktop apps (Paint): it fails with "the app does not support the contract" and was seen to end Paint's running instances (unsaved work). The drop code uses the registered `IAssocHandler` instead.
- Driving the item menu: open it with a real right-click (SafeClick-style check that WinDock is under the pointer), then find the menu window (`#32768`), get its `HMENU` with `MN_GETHMENU` (0x01E1) and press Down until `GetMenuState(id)` has `MF_HILITE`, then Enter. Send keys only while `GetForegroundWindow()` belongs to WinDock. Scripts: session scratchpad `p2\menu.ps1`, `p2\common.ps1`, `p2\t2.ps1` / `t7.ps1` / `t8.ps1`.
- Settings buttons that open a modal dialog (Choose icon…, Add…) must be pressed with `PostMessage(WM_COMMAND)`, not `SendMessage` (the call would block until the dialog closes). A dialog of WinDock's is the visible `#32770` of the WinDock process; close it with `PostMessage(WM_COMMAND, IDCANCEL)` when the foreground is not WinDock's. `GetWindowText` on another process's edit control returns nothing (use `WM_GETTEXT`).
- A modal dialog owned by the dock disables it: the dock then ignores clicks, and the dock must not re-assert `HWND_TOPMOST` (see 8.2). Any new dock-owned modal dialog should run through the same hold + CBT focus fix as `App::ChooseItemIcon`.
- Weather tests need the network (api.open-meteo.com, geocoding-api.open-meteo.com). Testing the widget writes `%LocalAppData%\WinDock\weather-cache.json`; delete it afterwards unless the user's config has `weather.show` on. The weather timer (id 20) is not an interaction timer: `QueryState` 5 stays 0 while it waits. To see the Stale state, restart the dock with a cache for the same place and units: `QueryState` 27 is 1 until the first fetch of the session completes (well under a second here), then 2. The widget's screen position is not queryable: take it from the last item's `QueryItemPoint` (+58 px at 100 %, clock about +125 px with the date shown) or from a screenshot, and check with SafeClick that WinDock is under the point. Take positions from the rest layout: `DockRect` while the mouse is on the dock is the whole stage, not the bar. Popups opened by `DockCommand` 114 / 115 can usually not take the foreground (as with `ItemCommand` 806); to test "another window comes to the foreground" without clicking another app, start a small WinForms window in a separate process and bring it forward with an Alt keypress + `SetForegroundWindow` (scratchpad `p3\form.ps1`, `p3\t2.ps1`).
- The Bash tool in this environment unescapes backslashes in command text (heredocs included): write files that contain backslashes (C++ escapes, JSON paths) with the Write tool, not `cat <<EOF` or inline Python.
- Building from the Bash tool: the documented `cmd /c '"...vcvars64.bat" && ...'` line silently does nothing there (Git Bash mangles `/c`; `MSYS_NO_PATHCONV=1` then breaks the quoting). Write a small `.cmd` (`call vcvars64.bat`, `cmake --preset`, `cmake --build`) into the scratchpad and run it from PowerShell: `& cmd /c <path>\build.cmd`.
- Before / after comparisons: build the previous commit in a scratchpad `git worktree add --detach <dir> HEAD` (its own `build\x64-release`), run it on the same config, and compare `QueryItemPoint` x per index plus `QueryState` 24: the bar is centred, so the widths of the clock / weather show up as shifted x values (the dock rect is useless while intelligent auto-hide keeps it hidden). Remove the worktree afterwards.
- Settings pages are created eagerly, so their controls can be driven while hidden: find them by id under `WinDock.Settings` with `EnumChildWindows` + `GetDlgCtrlID`, then `BM_SETCHECK` + `WM_COMMAND(id, BN_CLICKED)` to the control's parent; `LVM_GETITEMCOUNT` reads the Pinned list (scratchpad `settings.ps1`).
- A save drops theme keys whose value equals the preset's (existing override logic): the user's `"reflection": false` / `"perspective": false` under the `light` preset disappeared on the migration save. Expected, not a migration bug.
- PowerShell: never put `$(` inside a double-quoted regex (`"^    $(?=...)"` is a subexpression, the pattern degrades to `^    ` and strips indentation from every line). Use single quotes for regexes.
